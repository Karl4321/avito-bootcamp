# Avito Service Search: Candidate Generation (Retrieval)

Решение задачи кандидатогенерации для поиска услуг на Авито. **Цель:**
Для каждого поискового запроса отобрать до 50 наиболее релевантных
`item_id` из корпуса (\~189 000 объявлений). **Метрика:** Recall@50
(доля релевантных объявлений, попавших в топ-50; порядок внутри топа не
важен).

------------------------------------------------------------------------

## 🏆 Итоговое лучшее решение (Best Configuration)

После серии экспериментов было установлено, что **наилучшие результаты
показывает дообученная (fine-tuned) модель `intfloat/multilingual-e5-small`
в комбинации с текстом описания и *отключенным* историческим бонусом**.

**Оптимальный запуск `solution.py`:**

``` bash
python solution.py \
  --semantic-model ./e5-small-avito-finetuned \
  --semantic-desc-chars 300 \
  --train-bonus 0.0 \
  --sim-tfidf-weight 0.3 \
  --sim-sem-weight 0.7 \
  --run-name final_submission
```

*(Примечание: В процессе экспериментов отдельно проверялись разные
соотношения весов TF-IDF и Semantic-канала — сравнивались варианты с
равными весами (0.5/0.5) и конфигурации с большим весом semantic-канала
(0.3/0.7, 0.2/0.8); итоговое соотношение 0.3/0.7 подобрано эмпирически по
Recall@50 на offline-валидации. Также экспериментировались разные
конфигурации самой semantic-модели, включая zero-shot
`intfloat/multilingual-e5-small` и её fine-tuned версию.)*

## 🧠 Архитектура решения

Итоговый скор для пары (запрос, объявление) формируется как сумма
сигналов:

1.  **Semantic-канал (Основной):** Косинусное сходство L2-нормированных
    эмбеддингов модели `multilingual-e5-small`, дообученной на парах
    `(query, chosen_item)` из `train.parquet`. Модель использует
    префиксы `search_query:` и `search_document:`.
2.  **TF-IDF канал (Дополнительный):** Char-level TF-IDF (n-граммы 3-5
    символов). Спасает в edge-кейсах: редкие бренды, опечатки,
    специфические аббревиатуры, которые нейросеть может "размыть".
3.  **Структурные бустеры:** Аддитивные добавки за совпадение категории
    (`+1.0`) и локации (`+0.5`). Не являются жесткими фильтрами, чтобы
    не обнулять recall для запросов без точных гео-совпадений.

## 🚀 Как воспроизвести решение

### Шаг 1: Файнтюн модели (Training)

Запустите ноутбук `finetune_embeddings.ipynb`. Он выполнит следующее:

1.  Загрузит `train.parquet` и построит тексты с префиксами и описанием.
2.  Честно разделит данные на train/val **по уникальным текстам
    запросов** (предотвращение data leakage).
3.  Дообучит `intfloat/multilingual-e5-small` с использованием
    `MultipleNegativesRankingLoss`.
4.  Сохранит веса в локальную папку `./e5-small-avito-finetuned`.

*Требования:* модель компактная (\~118M параметров), поэтому подходит
GPU с небольшим объёмом VRAM; при нехватке памяти уменьшите `BATCH_SIZE`
в конфиге ноутбука.

### Шаг 2: Инференс и валидация (Inference)

Используйте скрипт `solution.py`, указав путь к сохраненной модели:

``` bash
python solution.py \
  --semantic-model ./e5-small-avito-finetuned \
  --semantic-desc-chars 300 \
  --train-bonus 0.0 \
  --sim-tfidf-weight 0.3 \
  --sim-sem-weight 0.7 \
  --run-name final_submission \
  --validate
```

### Шаг 3: Анализ результатов

После запуска откройте файл `experiments_log.csv`. В нём сохраняются
гиперпараметры каждого эксперимента, включая веса TF-IDF и semantic,
используемую модель, длину добавляемого описания и исторический бонус.
Это позволяет воспроизводимо сравнивать разные конфигурации и видеть,
как изменение весов и самой модели влияет на Recall@50. Файл
`answer.csv` будет готов к отправке.
